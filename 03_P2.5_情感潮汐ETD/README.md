# 情感潮汐解码（Emotion Tidal Decoding, ETD）

第三套独立架构：**概率空间 · 外部认知 · 解码期引导** + **回响 × 潮汐混合方案**

独立于语义回响项目已有的两套架构（五层架构 / 通用兼容层 V2），
走完全不同的路线——不在表示空间注入向量，而在**采样分布上做乘性重加权**。

## 三层架构

```
① 感知层 潮汐感知器.py   文本 → VAD 三维情感状态 + 会话轨迹（中英文词库）
② 决策层 潮汐决策器.py   共情目标 + 角色 VAD 基调主导 + 自适应 α + 词汇密度预算
③ 表达层 潮汐解码器.py   p'(w) = p(w)^(1-α) · q_emo(w)^α 乘性重加权 + 极性定向 + 在线兜底
④ 混合   混合注入器.py    回响(表示空间情感底色) + 潮汐(概率空间方向密度控制)
```

## v2.1 关键升级（基于实测缺陷修复）

1. **极性定向引导**：情感 token 表记录正/负极，只抬升与目标 valence 方向一致的词、
   抑制相反方向 → 解决 v1"所有情感词都被抬升导致错配分虚高"（净区分度↓）
2. **引导幅度修正**：强度扫描实测 k∈[1.0,2.5] 才有效 → 改用 `k = α × 引导倍率(12)`
3. **跨轮会话复用 + 角色 VAD 基调主导**：轨迹跨轮累积 + 人工标注角色基调主导
   （角色权重 0.6）→ 引导方向稳定贴合角色

## v4 关键升级（AI 腔三通道抑制——"像真人"制胜法宝）

诊断：LLM-Judge 裸模型 57% 回复含 AI 腔（"作为/我是/助手/模型"），是裁判判 AI 的主因。
单 token 抑制会被模型用近义表达绕过（"语言模型/模因/文本生成"），且强度过高产生谐音怪词。

**v4 三通道抑制**（治本而非治标）：
1. **首 token 黑名单**：第一 token 绝不以"作为/我是/抱歉/AI/语言"开头（×6 强压）
2. **decode 级过滤**：首 token 扫 top-300 候选，AI 腔开头一律 -inf
   （覆盖"作为一个/作为一名/如果你"等单 token 词表管不到的复合 token）
3. **短语感知**：近 3 token 若构成 AI 腔短语前缀（"作为"+"AI"），抑制 ×3
   （打"作为一个AI助手/语言模型"长短语）

## 核心公式

```
s_emo(w) = 情感词库极性得分          # +1 正面 / -1 负面
k = α × 引导倍率                    # v2.1：k∈[1.0,2.5] 有效区间
logits[方向一致情感词] += k          # 目标 valence 方向抬升
logits[方向相反情感词] -= 0.3k       # 抑制相反极性
logits[AI腔词]      -= 强度×权重      # v4：三通道 AI 腔抑制
```

## 实测结果（Qwen2.5-1.5B-Instruct 原版，无 SFT/LoRA）

### LLM-Judge（AI vs 真人盲评，全量 30 样本公平对比，60 次配对）
| 模式 | win_rate | rating | 提升 |
|---|---|---|---|
| 裸 | 0.1833 | 0.733 | — |
| 潮汐 v3（AI抑制2.0） | 0.2000 | 0.753 | +9% |
| **潮汐 v4.1（AI抑制4.0）** | **0.2333** | 0.747 | **+27%** |
| **混合 v4.2（λ0.08×倍率6+AI抑制4.0）** | **0.3500** | 0.767 | **+91%** ✓ |

混合 v4.2 达到 0.35：30 样本里 AI 在 60 次配对中赢下 21 次真人——接近翻倍。

## 横向测试（多模型泛化，20 样本同口径）

| 目标模型 | 裸 | 潮汐v4 | Δ潮汐 | 混合v4.2 | Δ混合 |
|---|---|---|---|---|---|
| Qwen2.5-1.5B | 0.200 | **0.275** | **+37.5%** | **0.375** | **+87.5%** |
| Qwen2.5-3B | 0.300 | **0.400** | **+33%** | 0.400 | +33% |
| Qwen3-1.7B | 0.575 | 0.550 | -4% | 崩溃* | — |

**横向结论**：
1. **潮汐单模式跨模型可用**（Qwen2.5 系显著提升 +33~37%，Qwen3 持平不降级）
2. **混合方案限 Qwen2 系**：1.5B +87.5%、3B +33%；Qwen3 架构下回响注入（hidden_state→vocab 投影）产生噪声导致重复崩溃，需适配钩子层
3. **增益与模型基础能力成反比**：弱模型（1.5B 裸 0.2）增益最大，强模型（Qwen3 裸 0.575）接近天花板
4. 同口径 20 样本验证 1.5B 混合 +87.5%（0.2→0.375），与 30 样本 +91% 一致 → 方案稳定非运气

## v6 关键升级（定向优化：身份暴露硬拦截 + 句子边界硬停止 + 身份拒绝 + 最小长度）

基于 60 样本实测诊断：混合输出仍有"我是一个语言处理系统/数字人/AI模型"类身份暴露（10% 样本拿 2 分），
且回复普遍 60+ 字长文（真人中位 20 字）——身份暴露 + 长度是最大破绽。

1. **身份暴露硬拦截（decode 级）**：生成文本尾部若处于"我是/作为一个/我的功能…"开启器后，
   下一 token 若是身份名词（AI/模型/系统/数字人/语料…）直接 -inf。只拦紧邻组合，
   正常句（"我是真的…"/"作为纪念"）不受影响。60 样本验证：身份暴露率 10%→<3%。
2. **身份暴露兜底清理**：完整身份短语仍漏网时，在上一句边界截断
   （"我不怕冷。我是一个语言模型…" → "我不怕冷。"）。
3. **句子边界硬停止（v6，替代负向的 v5 软促收尾）**：完整句子边界后即停
   （2 句且 ≥12 字；超 3 句必停；超 90 字强制停）。对齐真人 20-35 字风格。
4. **身份暴露定向拒绝采样（--身份拒绝）**：只对完整身份短语重生成（换种子），
   不碰书面语风格（旧的宽泛 AI 腔拒绝实测负向）。
5. **最小长度（v6.2）**：不足目标字数时压制 EOS 强制续写，防过早结束。

## v7 外挂层：gentle_v2 LoRA（Qwen2.5-1.5B 温柔陪伴适配器）

加载 `f:\lora外挂\lora_adapters\gentle_v2`（--LoRA 参数，PeftModel merge_and_unload），
基模从"正式书面语/分析式"转为"口语化陪伴腔"（"谢谢，你也这么认为吗？"/"没有，我还在工作"），
身份暴露率进一步下降（多数样本 尝试1 即通过）。

## v8 定向优化二轮（人设引导 + 身份v6.3 + 多候选自选 + 手动裁判加载）

三个新模块（全部正向增益）：
1. **人设系统提示（--人设）**：生成时注入"真人聊天风格"系统提示（口语化、短句、不自我介绍、
   不客服话术、不讲大道理）→ 直击 1.5B 服务腔/大道理两大低分主因（最大增益 +0.13~0.17）。
2. **身份拦截 v6.3（解码层补漏）**：开启器窗口扩大为"尾部 10 字内含开启器"，绕行名词补全
   （人类/人们/用户/知识库/无意识/编程/服务/阿里巴巴…）。修复 60-opt 漏网
   （"我是为人类解决问题/QA系统/无意识的存在/如果您有任何问题"等）。
3. **多候选自选（--自选N）**：每样本生成 N 个候选，按 人味评分（身份/AI腔重罚 + 长度取中 +
   口语词加分）选最优 → N3 比 N1 提升，N5 再提升。

裁判加载工程修复：低内存机（可用 4~8GB）上 from_pretrained 加载 7B 裁判在 torch_cpu.dll
固定偏移 0x6046edb 原生崩溃（0xC0000005，提交内存不足）。手动加载：meta 建模 → to_empty(cuda)
→ 逐分片 safetensors load_state_dict（CPU 峰值仅单分片）。**关键坑**：to_empty 只迁移结构，
`__init__` 计算的非持久化 buffer（Qwen2 旋转编码 inv_freq/original_inv_freq）变全零 →
必须按 rope_theta 重算，否则 logits 乱码。
