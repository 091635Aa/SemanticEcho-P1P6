- **声明**：`dynamic_策略.csv` 第 4 行描述写"动态(密度>0.30→τ0.05/λ+0.05)"
- **实际**：本次运行使用框架默认 λ 增量 0.02（`semantic_echo_framework.py` 已改，阈值 0.15/增量 0.02）
- **原因**：CSV 描述字段来自脚本策略表字符串；该次运行发生在 λ 增量修改前，实际注入仍是 λ+0.05
- **影响**：该 CSV 是"旧参数基线"数据（策略 C 熵 1.052、触发 3 次）；**校准复测（λ+0.02）已部署守护，结果将生成 `dynamic_策略_v2.csv`**
- **处理**：综合报告已注明"v2 校准待守护完成"；复核 agent 需在 v2 生成后更新判定

### 出入 2：7B LoRA 验证状态为"训练完成、验证待补"

- **声明**：checklist C13 标记为"训练完成，验证待补跑（守护已部署）"
- **实际**：`emotion_7B` 适配器存在（19.7MB safetensors），但 `emotion_emotion_7B_test_7B.json` 未生成
- **原因**：剪映占用 2.7GB+ RAM，7B 加载需 4-5GB CPU 缓冲，加载分片时 torch_cpu.dll 崩溃
- **处理**：守护进程（PID 28900）每 5 分钟检测，RAM≥5GB 自动补跑；复核 agent 需确认最终 JSON

### 出入 3：框架 λ 公式计算值 vs 实测最优

- **声明**：`λ = 0.5×(896/hidden_dim)^1.2`（框架自动计算）

- **出入**：公式方向正确但**普遍偏大 ~1.8 倍**，接近坍缩边缘
- **建议**：框架 v1.1 将指数改为 1.5（3B→0.139、7B→0.072，更接近实测），或引入扫描表覆盖
- **复核 agent 关注**：该出入不影响当前已验证结论（均用实测最优 λ），但影响框架开箱即用性
