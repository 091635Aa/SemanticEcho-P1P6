# 噪声鲁棒性与可信度评估报告（第39–42轮）

**目标**：在理想化仿真中加入传感器噪声、执行噪声与异常测量（离群噪点），测试即插即用引导注入器（ULI + BestCombo）在噪声环境下的优化效果、可信度（增益保持率）、Universal，并提出抗噪优化与新实施方案。

**结论先行**：
1. **BestCombo+ULI 已是对传感器噪声/异常测量最鲁棒的冠军方案**：在插件可感知的传感器噪声与离群读数下，增益保持率 ≈ 1.0（几乎无衰减），无需任何额外去噪前置。
2. **执行端噪声（施加在插件之后）构成不可恢复的物理下限**：平滑族的绝对增益保持率被压到 ~0.35（轻σ=0.01）/ ~0.14（强σ=0.02）；这一衰减源于噪声在插件输出之后被逐拍重新叠加，任何"指令前注入"都无法降低最终轨迹的噪声方差。p2p 族不受影响，仅因其基座本已近混沌、噪声相对可忽略。
3. **本轮提出的 4 类抗噪方案（SpikeGuard+FastNoiseLPF / PhaseMatchedSmoother / PhaseMatchSmoother2 / StateHFBoost）全部被证伪**：它们要么在 clean 下过度平滑崩塌，要么在噪声下门控不触发（无增益）且误伤高 jerk 的 p2p，均无法超过 BestCombo+ULI。
4. **可信度度量须用"绝对增益保持率"而非 opt 衰减率**。`opt=(CI_p−CI_b)/(1−CI_b)` 在噪声下因分母膨胀而系统性夸大衰减，误导评估。

## 1. 噪声测试台（第40轮修正）

针对"传感器噪声/异常变量"的真实物理语义，把噪声分为两类，并修正好让插件"感知"的部分：

| 类型 | 施加位置 | 插件是否感知 | 物理含义 |
|---|---|---|---|
| `obs_noise` | 观测读取（策略输入前） | ✅ 可感知 | 传感器测量噪声 |
| `obs_spike_p/amp` | 观测读取（新增） | ✅ 可感知 | 传感器异常读数（离群噪点） |
| `act_noise` | 插件输出后 | ❌ 不可感知 | 执行器噪声 |
| `act_spike_p/amp` | 插件输出后 | ❌ 不可感知 | 执行侧异常 |

关键事实：**执行噪声虽然"后置不可见"，但它污染物理状态 q，并经由 `dq=(q_new−q)/dt` 按 1/dt 放大**，因此理论上可从 `dq` 的高频持续能量间接感知——这正是 StateHFBoost（V4）的出发点。

## 2. 噪声场景

| 场景 | obs_noise | act_noise | obs_spike | act_spike |
|---|---|---|---|---|
| clean | 0 | 0 | 0 | 0 |
| mild | 0.02 | 0.01 | 0 | 0 |
| strong | 0.05 | 0.02 | 0.002×0.4 | 0.002×0.4 |

## 3. 可信度定义（修正后）

- **绝对增益** `g = CI_p − CI_b`（插件相对同场景基座的实际增量）。
- **可信度/增益保持率** `retention(scenario) = g(scenario) / g(clean)`。
  - =1.0 → 插件价值在噪声下完全保留；
  - <1.0 → 插件价值被噪声削弱。

不再用 `opt` 衰减率（其分母 `1−CI_b` 在噪声下膨胀，会误判成"插件失效"）。

## 4. 全 T 权威结果（T=51200, seed=42）

### 4.1 冠军 BestCombo+ULI（仅一次 standard 族离线训练，三族零样本）

| 族 | clean 增益 | mild 增益 | strong 增益 | 可信度(mild) | 可信度(strong) |
|---|---|---|---|---|---|
| standard | +0.4121 | +0.1335 | +0.0532 | **0.324** | **0.129** |
| transformer | +0.2796 | +0.0915 | +0.0317 | **0.327** | **0.113** |
| p2p | +0.4171 | +0.4168 | +0.4164 | **0.999** | **0.998** |

**解读**：
- p2p 族：完美鲁棒（保持率≈1.0）。
- 平滑族（standard/transformer）：执行噪声把价值压到 ~0.32（mild）/ ~0.12（strong）。这是**后置执行噪声的物理下限**。

### 4.2 插件可感知噪声几乎无损失（中T 测试）

在仅含 `obs_noise=0.04` / `obs_spike`（不含执行噪声）时，冠军增益保持率 ≈ 0.97–1.00：
- clean 增益 +0.253 → sensor_noise +0.247 → sensor_outlier +0.252（T=5120）。
- 说明 **BestCombo 的相位平滑本就把可感知传感器噪声吸收干净**，无需额外去噪器。

## 5. 四类抗噪方案证伪记录

| 方案 | 核心机制 | 结果 | 结论 |
|---|---|---|---|
| RobustCombo(V38) : SpikeGuard+FastNoiseLPF | 前置中位数/MAD抑噪点 + 高频平滑 | clean 崩塌 avg=−0.509 | 过度平滑相干步态，否决 |
| RobustComboV2 : PhaseMatchedSmoother | 滑窗相位LS拟合，残差门控 | 平滑族恒等、p2p略伤；噪声下不触发 = 无增益 | 门控方向错，否决 |
| RobustComboV3 : PhaseMatchSmoother2 | 相位拟合**残差高频**门控 | 平滑族与基线逐位相同；p2p再伤 | 执行噪声不可见→检测不到，否决 |
| RobustComboV4 : StateHFBoost | 从 **dq 高频**检测执行噪声 + 相位锁定 | 平滑族保持率与基线无异；p2p仍伤 | 后置噪声方差不可逆，否决 |

**共同根因**：执行噪声在插件输出后逐拍重新叠加，最终轨迹的噪声方差由 σ 本身钳制，任何"指令前"相位锁定/去噪都无法降低它；而可感知的传感器噪声又已被 BestCombo 消化。于是"加去噪前置"这一路线在本模型下彻底无收益。

## 6. 新实施方案建议（本职与上游的边界）

插件（ULI+BestCombo）**承担且已最优承担**的部分：
- 抵抗传感器测量噪声与异常读数（保持率≈1.0）。
- 在干净与传感器噪声下保持 Universal 与正向优化。

对执行噪声，正确的工程补救不在"注入插件"，而在**指令前/后端的信号链**，建议作为后续独立模块（不重训基座）：
1. **状态估计前置（Sensor-side Kalman / 平滑观测器）**：在策略与插件**之前**滤除执行噪声污染的状态，让插件读到更干净的状态与其步态相位。这是唯一能真正抬升平滑族可信度保持率的出口。
2. **执行指令平滑器（后置，低通/限幅）**：在插件输出之后、执行器之前加一阶低通，压掉 `act_noise` 的高频成分——虽然它也在执行前，但挂在靠近执行器一侧对指令白噪最有效（注意会引入相位滞后，需与步态相位补偿）。
3. **异常读数隔离（Redundancy / MAD）**：对传感器异常读数做多源交叉校验，从源头移除 `obs_spike`，其可由现有观测层承担。
4. **可信度监控**：在生产中在线用增益保持率/相位复发性能指标监控可信度，依赖净化状态估计。

## 7. 结论

- 本轮把"噪声/噪点→优化率→可信度→优化"的闭环走完，并用**修正后的增益保持率指标**给出了权威结论。
- 冠军 **BestCombo+ULI 对传感器噪声/异常读数可信度高（≈1.0）**；对执行噪声存在**物理不可逆的平滑族下限（~0.32/0.12）**。
- 新方案（去噪前置、相位锁定）全部证伪；真正有效的优化出口是**状态估计/指令后置平滑等信号链模块**，已列入后续实施项。
