# P6 重点② 情感 LoRA 外挂 × 旁路由选优（Emotion LoRA + Bypass Routing）

> **一句话**：家族里**唯一"训练态"方案**——训练情感 LoRA 适配器写入权重 + 推理期旁路由（多候选情感评分选优）。与前辈"解码期零权重注入"本质不同，且满足"前奏不可修改"。
> **操作空间**：权重空间（训练）+ 路由空间（推理）｜ **改权重**：LoRA 适配器（基座零改动）｜ **当前状态**：达标迭代中（win_rate 0.35，目标 ≥0.48）。

---

## 1. 核心机制

1. **训练数据管线**：情感 4409 + 温柔 80 + 人味增强 132 = **4557 条** chat 格式（`data/p6_train.jsonl`）；
2. **LoRA 训练**：Qwen2.5-1.5B 基座，r=8 / α=16，3 epoch，q/k/v/o，回复掩码监督（`lora_adapters/p6_emotion/`）；
3. **旁路由生成器**：主路径零注入，用 LoRA 挂载模型生成 **N=3 候选**（种子 2026 + 序号 + k×7），情感路由评分选最优；
4. **路由评分**：情感命中 2.5 / 长度 1.2 / AI腔 -1.0/词 / 重复 -3.0；
5. **裸采样兜底**：全部候选不合格时降级裸采样，保证不坍缩。

**与前辈的本质区别**：前辈全是"解码期零权重注入"（不训练）；P6 LoRA 首次**训练写适配器权重**，然后靠**侧路选优**而不是改主路径。

## 2. 优点

- **底层思路本质不同**：训练态写权重 + 旁路由选优，满足"与前辈不同"的硬要求；
- **前奏零修改**：不碰 system prompt / chat 模板，能力全在外挂适配器 + 侧路选优；
- **健康度好**：旁路由模式重复率 0.000、兜底 0；LoRA 裸模式熵 4.376（表达多样性高）；
- **初版即正收益**：P6_旁路由 win_rate 0.35 > 裸 0.1833（+91% 相对裸），LoRA 裸 0.3333 也超裸；
- **管线完整可迭代**：数据→训练→生成→裁判→汇总全自动，支持 r/α/epochs/N 扫描（上限 5 轮迭代）。

## 3. 缺点与局限（当前）

- **未达达标线**：目标 win_rate ≥ 0.48，当前 0.35（差 0.13）；
- **辅助指标未全达**：情感命中 0.131（目标 ≥0.20）；长度 33 字（目标 20~80 字内，偏短）；
- **LoRA 裸模式命中率反降**：0.082 vs 裸 0.136——纯 LoRA 情感词浓度不足；
- **训练成本**：需 GPU 训练 + 断点管理；数据量小（4557 条）；
- **单基座验证**：仅 Qwen2.5-1.5B，未跨模型验证。

## 4. 适用场景

- **产品化"永久升级"**：想要模型文件层面永久拥有情感能力（不改前奏）的场景；
- 批量部署多实例时的**零推理期开销**（训练一次，推理无注入开销）；
- 与解码期方案（EDD/P2.5）**双保险叠加**（训练态打底 + 解码期精修）。

## 5. 不适用场景

- 不能重新训练/无 GPU 的环境（应选 EDD 解码期插件）；
- 需要"不改任何文件、即插即用"的场景；
- 当前版本的高胜率竞技场景（未达标前不宜直接上生产）。

## 6. 跑分效果（P6_LLMJudge_30.json，2026-08-11，种子 2026，7B 裁判 60 配对/模式）

| 模式 | win_rate | 胜/总 | 熵 | 重复率 | 情感命中 | 长度(字) |
|---|---|---|---|---|---|---|
| 裸 | 0.1833 | 11/60 | 2.419 | 0.009 | 0.136 | 104.0 |
| P6_LoRA裸（消融） | 0.3333 | 20/60 | 4.376 | 0.004 | 0.082 | 34.9 |
| **P6_旁路由** | **0.35** | 21/60 | 4.221 | **0.000** | 0.131 | 33.1 |

> 相对裸 +91%，但未达 P6 达标线（win_rate ≥ 0.48 / 情感命中 ≥ 0.20）。**待迭代**：增补人味对话数据（p6_augment.jsonl）、调路由权重（AI腔惩罚加重）、超参扫描（r/α/epochs/N）。

**同家族的参考**：P6 EDD（解码期）已以 0.7046 综合夺冠——LoRA 外挂与之是"训练态 vs 解码期"两条互补路线。

## 7. 边际效益分析

- **训练数据的边际递减**：4409 情感条→4557 条，增量数据对命中率的边际贡献递减；需补充"人味/短回复"类样本才能拉高情感命中（当前 0.082~0.131）；
- **多候选 N 的边际**：N=1→3 是最大一跳（旁路由 0.35 vs LoRA 裸 0.3333 已体现），N=3→5 预计收窄；
- **路由权重调参的边际**：AI腔 -1.0/词、重复 -3.0 的惩罚是"最后一公里"边际，越调越平；
- **LoRA 超参的边际**：r/α/epochs 扫描存在最优区间，超出后边际为负（过拟合/遗忘）；
- **训练态 vs 解码期的边际对比**：EDD（解码期，0.7046）当前边际 >> LoRA（训练态，0.35）——训练态路线需要更大数据/更强训练才可能反超。

## 9. 测试方法（完整流程）

1. **生成**：`06_P6_LoRA外挂_旁路由/核心/P6生成_30条.py` → `P6_生成_30.json`；
2. **裁判**：`P6裁判_30条.py`（7B 裁判 AB 配对 ×2，断点续跑 + GPU 让路）→ `P6_LLMJudge_30.json`；
3. **汇总**：`P6汇总.py` → 终端输出 P6 vs 全体前辈对比 + 达标判定；
4. **迭代**（未达标按序）：① 增补数据重训（`p6_gen_data.py` + `p6_train_lora.py`）→ ② 调路由权重（`P6旁路由.py`）→ ③ 超参扫描（r∈{8,16} α∈{16,32} epochs∈{2,4} N∈{2,5}）→ 每轮重跑 生成→裁判→汇总；
5. **GPU 纪律**：显存 <2000MB 且利用率 <10% 才运行；让路标记 `C:\P6临时盘\让路.flag`。
