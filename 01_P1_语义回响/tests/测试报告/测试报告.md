## 问题与解决方案

| 编号 | 问题描述 | 严重程度 | 状态 | 解决方案 |
|------|---------|---------|------|---------|
| 1 | `实验对比器.设置基线()` API 仅接受评估器参数，不接受额外的文本参数 | 低 | 已解决 | 修正测试脚本，仅传入评估器参数 |
| 2 | 情感命中率统计需先调用 `自增检查()`，直接 `添加()` 不增加总检查数 | 低 | 已确认 | 此为设计预期：总检查数由 `采样处理器.py` 中的 `捕获回响` 流程控制，并非池内部自动统计 |
| 3 | 确定分布熵值为 -0.000000（极小负值），非严格0 | 低 | 已确认 | 数值稳定性问题，由 softmax 数值精度引入，不影响功能 |

## 建议

1. **采样处理器完整功能测试**：当前模块4仅完成了语法和类结构测试。建议加载实际 HuggingFace 模型（如 Qwen2.5-1.5B）后运行端到端生成测试，验证 `回响注入器.生成()` 的正确性。

2. **情感过滤器性能**：cnsenti 每次调用 `sentiment_count()` 都触发 jieba 分词，对于高吞吐场景可能成为瓶颈。建议在需要高频筛选时考虑批量处理或缓存机制。

3. **增长测试覆盖率**：当前测试覆盖了各模块的核心功能和异常路径，但仍有以下场景未覆盖：
   - 回响池的 `清空()` 方法
   - 回响池的情感相关性列表与向量列表不同步时的边界情况
   - 情感过滤器的 `计算权重()` 方法
   - 汇总统计器的 `从JSON加载()` 方法
   - 异常 JSON 文件的解析错误恢复

4. **自动化回归测试**：建议将 `全面测试.py` 纳入 CI/CD 流水线，在每次修改关键模块后自动执行，确保功能一致性。
