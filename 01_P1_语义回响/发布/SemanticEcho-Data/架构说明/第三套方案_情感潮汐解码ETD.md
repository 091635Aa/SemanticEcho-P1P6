# 第三套方案：情感潮汐解码（Emotion Tidal Decoding, ETD）

> 独立于"五层架构"与"通用兼容层 V2"的第三套架构方案
> 版本：2026-08-09 v1.0 | 定位：**概率空间 · 外部认知 · 解码期引导**
> 从 0 → 1 → 完工 完整实施路径

---

## 一、为什么需要第三套：两套现有架构的本质

| | 五层架构（第0层+第1层语义回响） | 通用兼容层 V2 | 情感潮汐解码 ETD（本方案） |
|---|---|---|---|
| 操作空间 | **表示空间 + 权重空间** | **配置空间** | **概率空间** |
| 核心机制 | hidden_state 钩子 → 回响池质心 → `logits += 质心@投影×λ` | 扫描表/因子表/公式归一化 λ、γ、τ | 采样分布重加权 + 情感词预算 |
| 情感来源 | 模型**自身**的 hidden_state（自我回响） | 同左（调参） | **外部**情感认知（VAD 状态机） |
| 是否需要本地权重 | ✅ 必须（钩子读 hidden_state） | ✅ 必须（同机制调参） | ❌ 可选（闭源 API 也能用） |
| 坍缩风险 | 高（Qwen3-1.7B 曾 重0.84） | 已用因子缓解 | **天然低**（概率重加权有界） |
| 可解释性 | 低（向量池是黑盒） | 中 | **高**（显式情感状态机可审计） |

**一句话定位**：架构一让模型"回想自己的情感再表达"（内循环），架构二给这个内循环调参，
而本方案让模型"感知对话中的情感潮汐，在采样时主动涌向情感目标"（外循环 + 概率引导）。

**灵感来源**：完全脱胎于本项目的语义回响思想（情感先于表达），但把"情感载体"
从「模型 hidden_state 向量」换成「外部连续情感状态 + 词汇分布」——从而摆脱了
对隐藏层钩子、随机投影矩阵、回响池的全部依赖，做到**跨本地/闭源模型统一可用**。

## 二、总体架构（三层）

```
┌─────────────────────────────────────────────────────────────┐
│                    情感潮汐解码引擎 (ETD)                       │
│                                                             │
│  ① 感知层：情感潮汐测量器                                       │
│     输入：用户消息 + 已生成文本                                  │
│     输出：连续情感状态 V(t) = (valence, arousal, dominance)     │
│           + 情感关键词序列 + 会话情感轨迹                        │
│                                                             │
│  ② 决策层：潮汐目标计算器                                       │
│     输入：情感轨迹 + 角色基调 + 表达节奏设定                      │
│     输出：目标情感分布 q_emo(t) + 自适应引导强度 α(t)             │
│                                                             │
│  ③ 表达层：潮汐解码器                                           │
│     解码期重加权：p'(t) ∝ p(t)^(1-α) · q_emo(t)^α              │
│     + 情感词预算控制（整句级密度）                               │
│     + 在线退化兜底（自动调 α）                                  │
└─────────────────────────────────────────────────────────────┘
```

三层各自独立成模块，**不修改任何现有源码**（语义回响/推理框架/评测脚本均不动），
新增文件即可挂接，与架构一、架构二**正交**——可单独用，也可叠加验证。

## 三、模块详细设计

### 3.1 感知层：情感潮汐测量器（`潮汐感知器.py`）

**目标**：把文本对话转成显式、连续、可追踪的情感状态。

**输入**：用户消息（每轮）与模型已生成文本（流式每句）。
**处理**：
1. **VAD 情感投影**：对整段文本做情感词加权，得到三维连续状态
   `V = (valence 愉悦度, arousal 唤醒度, dominance 支配度) ∈ [-1,1]³`
   - 词典基础：复用 cnsenti 情感词库（与现有情感过滤器同源，保持统计口径一致）
   - 加权方式：情感词强度 × 位置权重（越靠近当前句权重越高，指数衰减，窗口 τ_感）
2. **情感轨迹维护**：`轨迹 = [V(0), V(1), ..., V(t)]`
   - 记录对话情感随时间的变化——"潮汐"的涨落
   - 轨迹容量固定（如 32 轮），旧状态指数遗忘
3. **关键词提取**：当前窗口内命中情感词库的高强度词，供裁判审计与解释

**与架构一的本质区别**：架构一读的是模型**内部** hidden_state（每 token 一次钩子），
本方案读的是**文本层**情感（每句一次，成本可忽略），不侵入模型内部，因此
**不依赖任何本地可读隐藏状态的模型**——闭源 API 同样适用。

**模块接口**：
```python
class 潮汐感知器:
    def __init__(self, 词库="cnsenti", 窗口=32, 位置衰减=0.9): ...
    def 测量(self, 文本: str) -> 情感状态: ...      # → (V, 关键词)
    def 追加轨迹(self, 说话人, 情感状态): ...        # 维护会话轨迹
    def 当前潮位(self) -> 情感状态: ...              # 加权最新状态
```

### 3.2 决策层：潮汐目标计算器（`潮汐决策器.py`）

**目标**：根据轨迹 + 角色设定，算出"此刻该涌向哪里"的目标分布与引导强度。

**输入**：情感轨迹、角色基调（可选，默认共情）、用户当前情感。
**处理**：
1. **共情目标**：`V_target = V_用户当前 × β_共情 + 轨迹均值 × (1 - β_共情)`
   - β_共情 控制"贴近用户" vs "保持自身情绪稳定"，默认 0.6，可调
2. **角色基调叠加**：若配置角色（如"温柔"），目标向量朝角色 VAD 基线收敛
3. **引导强度自适应**（替代架构一的固定 λ）：
   ```
   α(t) = α_基 × (1 + Δarousal) × min(1, 轨迹活跃度)
   ```
   - Δarousal：用户情感越强（唤醒度高），引导越强
   - 轨迹活跃度：最近 N 轮 VAD 位移之和，避免冷场时过度引导
4. **词汇预算**：`密度目标 = 密度_基 + 密度_增益 × |V_target|`
   - 情感越强 → 允许/期待更多情感词，但封顶（防堆砌）

**输出**：`目标情感状态 V_target`、`引导强度 α(t)`、`词汇密度目标`。

### 3.3 表达层：潮汐解码器（`潮汐解码器.py`）

**目标**：在采样时让分布向情感目标涌去，同时控制情感词密度。

**核心公式（概率空间重加权，非 logits 加法）**：
```
对每个候选 token w：
    s_emo(w) = 情感词库得分（命中词 → 强度；未命中 → 0 附近的噪声基线）
    q_emo(w) = softmax( s_emo(w) / T_emo )          # 情感引导分布
    p'(w)    = p(w)^(1-α) · q_emo(w)^α / Z          # 乘性重加权，Z 归一化

其中 α = α(t)（决策层动态给出，默认 α_基=0.15 量级，远小于注入系数的敏感度）
```

**为什么用乘性重加权而不是 logits 加法**：
- logits 加法（架构一）会把偏置强加到每个候选上，小模型上容易碾压原分布 → 坍缩；
- 乘性重加权是有界插值（α∈[0,1] 时 p' 介于 p 与 q_emo 之间），**数学上不可能坍缩**，
  只会把概率质量向情感词倾斜——对应评测里的"情感命中率"指标直接受益。

**情感词预算控制（整句级）**：
- 对每个句子，统计已生成情感词数 n_emo 与句子长度 L
- 当前密度 = n_emo / L；若当前密度 > 密度目标：把 q_emo 中的词汇得分压低（乘 0.5），
  让分布回落到中性表达；若 < 目标下限：微抬情感词得分。
- 作用：避免"通篇是情感词"的机械感，保持自然度（对应语义熵不退化）。

**在线退化兜底（每句检查）**：
- 监测重复率（n-gram 重复）与语义熵；若熵 < 0.6 或重复率攀升 → α × 0.5 重试；
  连续 3 次仍退化 → α = 0（退化为纯裸采样），保证任何模型不掉线。

**模块接口**（与回响注入器签名对齐，便于评测脚本无痛接入）：
```python
class 潮汐解码器:
    def __init__(self, model, tokenizer, 感知器, 决策器,
                 α基=0.15, T_emo=0.3, 密度基=0.06, 密度增益=0.10): ...
    def 生成(self, input_ids, max_new_tokens=256, temperature=1.0,
             top_p=0.9, top_k=50, repetition_penalty=1.0, ...) -> torch.Tensor
```

### M5f 潮汐 v4（AI 腔三通道抑制）——"像真人"制胜法宝
诊断：裸模型 57% 回复含 AI 腔（"作为/我是/助手/模型"），是 LLM-Judge 裁判判 AI 的主因。
单 token 抑制会被模型用近义表达绕过（"语言模型/模因/文本生成"），强度过高则产生谐音怪词
（"人工智障/语言 model"）。

**v4 三通道抑制**（治本而非治标）：
1. **首 token 黑名单**：第一 token 绝不以"作为/我是/抱歉/AI/语言"开头（×6 强压）
2. **decode 级过滤**：首 token 扫 top-300 候选，decode 后 AI 腔开头一律 -inf
   （覆盖"作为一个/作为一名/如果你"等单 token 词表管不到的复合 token）
3. **短语感知**：近 3 token 若构成 AI 腔短语前缀（"作为"+"AI"），抑制 ×3
   （打"作为一个AI助手/语言模型"长短语）

**LLM-Judge 全量 30 样本（60 配对）v4 成果**：
| 模式 | win_rate | rating | 提升 |
|---|---|---|---|
| 裸 | 0.1833 | 0.733 | — |
| 潮汐 v3（AI抑制2.0） | 0.2000 | 0.753 | +9% |
| **潮汐 v4.1（AI抑制4.0）** | **0.2333** | 0.747 | **+27%** |
| **混合 v4.2（λ0.08×倍率6+AI抑制4.0）** | **0.3500** | 0.767 | **+91%** ✓ |

→ **混合 v4.2 胜率 0.1833 → 0.35，AI 在 60 次配对中赢下 21 次真人，接近翻倍**

**EmoCharacter 混合 v4.2**：一致性识别率 **0.8**（裸 0.6，+33%）、真实一致性 0.956、
匹配fidelity 0.87、中性下限 0.72。AI 腔抑制未损害情感能力，反而因"更像角色"提升识别率。

**AI 腔抑制强度扫描**（30 条）：0.0→13/30 命中；4.0→2/30 命中（v4 后）；6.0/8.0 饱和不降
且产生谐音怪词 → 最优 4.0。

1. 身份暴露硬拦截（decode 级，开启器+身份名词紧邻 -inf，外科手术式不误伤正常句）
2. 身份暴露兜底清理（上一句边界截断）+ 身份暴露定向拒绝采样（--身份拒绝，只拒身份短语）
3. 句子边界硬停止（2 句即停，替代负向的 v5 软促收尾）+ 最小长度（v6.2，不足压制 EOS 强制续写）

**v7 外挂层**：gentle_v2 LoRA（Qwen2.5-1.5B 温柔陪伴适配器，`--LoRA` 参数 merge_and_unload），
基模转口语化陪伴腔，身份暴露率进一步下降。

**实测（8bit 裁判同口径）**：

| 基准 | 配置 | win_rate |
|---|---|---|
| 60-opt N30 | 裸 | 0.2667 |
| 60-opt N30 | 混合 v6 | **0.3333**（+25%） |
| 60-opt N30 | 混合 v6 + LoRA | **0.3500**（+31%） |
| 60-opt N30 | 3B 混合 v6 | 0.4667 |
| 60-opt N30 | Qwen3 潮汐 v6 | 0.5833 |
| 30-set N20 | 混合 v6 | 0.275 |
| 30-set N20 | 混合 v6 + LoRA | **0.3500**（+27%） |

**结论**：定向优化全部正向增益（裸→混合→+LoRA 单调递增）；但 LLM-Judge 盲评上 1.5B+LoRA（0.35）
未反超 3B（0.40/0.47）与 Qwen3（0.55/0.58）——基模表达自然度/内容深度是硬瓶颈，解码期引导+外挂只能缩小差距。
Qwen3 混合模式仍因回响注入退化重复（改用潮汐）。

### M5i v8 定向优化二轮（人设引导 + 身份v6.3 + 多候选自选 + 手动裁判加载，2026-08-09）

**诊断（60-opt 实测）**：v6 身份拦截"开启器=尾部后缀"判定缺陷 → "我是为人类解决问题/你算我整个QA系统/
我是一个无意识的存在/如果您有任何问题"等绕行漏网；服务腔/大道理仍是低分主因。

**v8 三个新模块（全部正向增益）**：
1. **人设系统提示（--人设，prompt 级架构优化）**：注入"真人聊天风格"系统提示（口语化、短句、
   不自我介绍、不客服话术、不讲大道理）→ 直击服务腔/大道理（最大增益 +0.13~0.17）
2. **身份拦截 v6.3**：开启器窗口扩大为"尾部 10 字内含开启器"，绕行名词补全
   （人类/人们/用户/知识库/无意识/编程/服务/阿里巴巴…），清理正则同步扩充
3. **多候选自选（--自选N）**：每样本 N 候选按 人味评分（身份/AI腔重罚+长度取中+口语加分）选最优

**裁判加载工程修复**：16GB 内存机可用 4~8GB 时，from_pretrained 加载 7B 裁判在 torch_cpu.dll
固定偏移 0x6046edb 原生崩溃（0xC0000005）——提交内存不足（bnb 8bit 需 ~14GB 瞬时驻留）。
**手动加载**：meta 建模 → to_empty(cuda) → 逐分片 safetensors load_state_dict（CPU 峰值仅单分片）。
**关键坑**：to_empty 只迁移结构，`__init__` 计算的非持久化 buffer（Qwen2 旋转编码
inv_freq/original_inv_freq）变全零 → 须按 rope_theta 重算，否则 logits 乱码（实测权重逐值核对+推理验证通过）。

**实测（60-opt 样本集，bf16 手动裁判同口径）**：

| 基准 | 配置 | win_rate | 增益 |
|---|---|---|---|
| N30 | 混合 v6 风格（无人设，N5） | 0.3500 | — |
| N30 | 混合 v8 + 人设（N3） | 0.4833 | +38% ✓ |
| N30 | **混合 v8 + 人设（N5）** | **0.5167** | **+48%** ✓ |
| N30 | Qwen3 潮汐 v8 | 0.5333 | — |
| N30 | 3B 混合 v8 | 0.3500 | — |
| N60 | 混合 v8 + 人设（N5） | 0.4250 | — |
| N60 | Qwen3 潮汐 v8 | 0.4917 | — |

**结论**：① 同裁判下 0.35→0.4833→0.5167 严格单调（全部正向增益，人设是最大来源）；
② **反超 3B 达成**（N30 0.517 vs 0.35、N60 0.425 vs ~0.35）；③ Qwen3 未反超（N30 差 1 配对
噪声内、N60 落后）——v8 对 Qwen3 有 emoji/`<think>` 干扰使其从裸 0.58 回落，但基模自然度天花板
仍更高；④ 样本 v3 校准实验为负向（0.5167→0.4667），维持 60-opt 集；⑤ 1.5B 表达力是最终瓶颈，
解码期引导 + prompt 人设 + 外挂 LoRA 已把 1.5B 拉到与 Qwen3 统计持平的水平。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 情感词库稀疏，q_emo 覆盖不足 | 词库与架构一同源，且 T_emo 平滑分布；未命中词退回 p(w) |

| 裁判偏好（7B 裁判风格偏差） | 沿用"裸/四层"同协议对照，相对比较而非绝对分数 |
