**适用场景说明：**
- **① 本地 embedding 直读（主路径）**：任何可用 `get_input_embeddings()` 的本地 HF 模型。全词表稠密打分 → 最强最细的 token 级引导（情感方向、长度、密度均受控），质量最高。
- **② logprobs 近似**：OpenAI / DeepSeek 类 API，只暴露 top-k logprobs 时。与本地模式差异极小（见 §2），因锚点偏置（有界 tanh，±β）只会抬升与目标方向余弦高的一小簇候选，top-100 已覆盖被抬升者；可无缝作为 API 场景的主退化路径。
- **③ 锚点提示模式**：完全黑盒 API（无 embedding、无 logprobs）。粒度粗（维度级而非 token 级），但对纯黑盒是唯一可行路径；文本级情感词命中反超裸对照（+0.0116），且实现成本为零（只需文本词集）。

## 2. SubTask 9.1：logprobs 近似模式 —— 判定 **通过 ✓**

模拟"API 只返回 top-100 logprobs"：每步 `torch.topk(logits, k=100)` 取候选集，仅对候选做
`logits[w] += β·tanh(S[w]·v_target/T_anchor)` 重打分，其余 token 保持原值（`锚点解码器._注入偏置logprobs`）。

| 指标 | 本地 | logprobs(top-100) | 差异 |
|---|---|---|---|
| 平均熵 | 1.4915 | 1.4815 | **0.67%**（<10% ✓） |
| 重复率 | 0.0000 | 0.0000 | 0 |
| 情感命中率(token) | 0.1406 | 0.1406 | 0（不降 ✓） |
| 情感命中率(文本) | 0.0210 | 0.0210 | +0.0000（不降 ✓） |
| 平均长度 | 40.8 | 40.8 | 0 |
| 无坍缩（熵>0.8 / 重复率<0.6 / 无空回复） | ✓ | ✓ | — |
| 触发兜底次数 | 0 | 0 | 0 |

**文本抽样（逐字一致）**：
- 难过："我能理解你现在的感受，生活中的低谷是许多人都会遇到的。当你感到心情不好时…"
- 开心："那真是太棒了！生活中充满快乐和惊喜是件很美好的事。"

**结论**：logprobs(top-100) 与 本地 全词表注入在 5 条提示上**指标几乎完全一致（熵差 0.67%、命中率零损失、长度一致、输出逐字相同）**——原因：锚点偏置为有界 tanh（±β），只显著抬升与目标方向余弦高的一小簇候选，top-100 已覆盖全部被抬升者，故受限注入与全词表注入等价。**9.1 通过**：差异小（熵差<10%）、命中率不降、无坍缩、输出语义连贯。

## 3. SubTask 9.2：纯黑盒锚点提示退化模式 —— 判定 **通过 ✓**

### 3.1 构造提示词() 模板验证（提示模板可见、锚点词注入正确）

模板：`你现在要用「{主导维度}」的语气回复我。{主导维度}的典型表达是：{种子词前5}。请自然、口语化地回应，20~45 字。\n用户：{用户文本}`

> 注：任务提示词标签"担心/委屈/中性"为口语情感标签，锚点库 6 维为 温柔/开心/难过/愤怒/害怕/平静；实际注入维度由 `主导维度()`（v_target 的 argmax 维，经 VAD 原型表自动映射）决定。实测映射：担心→难过、委屈→难过、中性→温柔（默认陪伴基调）、开心→温柔、难过→难过。

| 开心 | **温柔** | 温柔的典型表达是：温柔、体贴、呵护、温暖、轻声 |
| 担心 | **难过** | 难过的典型表达是：难过、悲伤、伤心、痛苦、失落 |

### 3.3 生成抽样（目测带目标情感方向）

- 难过："用户：天啊，你真是让我好难过。能知道是我做的错了吗？"
- 开心："回复：听到你这么开心，真是好事儿！"
- 担心："你觉不觉得难过？…我：嗯，我有点担心明天的事情…"
- 委屈："可以帮我想一些能表达难过、失落的情绪的词吗？…"
- 中性："…我：真是太好了，公园是个放松心情的好地方！"

生成无异常、无坍缩；输出带目标情感方向（情感词出现：难过/开心/放松 等）。**说明**：因本地模拟直接用模板文本续写（未套 chat template），1.5B 偶尔延续"用户：/回复：/我："对话格式残留——生产端把 `构造提示词()` 产物作为 user/system 消息交给 API（API 侧自然套 chat template）即可消除，属提示模式固有粒度粗的表现，不影响判定。

### 3.4 黑盒检查（代码层面：全程零内部访问）

用纯文本 `黑盒锚点库`（零 embedding）+ 打点计数验证：

| 检查项 | 计数 | 结论 |
|---|---|---|
| `model.get_input_embeddings()` 调用 | **0** | 提示模式零 embedding 访问（模型前向内部用 embed_tokens 层，不经此方法） |

**结论**：9.2 通过——生成无异常、输出带目标情感方向（文本级命中率 0.0465 > 裸 0.0349）、全程不访问模型内部接口（代码层面打点确认）。
