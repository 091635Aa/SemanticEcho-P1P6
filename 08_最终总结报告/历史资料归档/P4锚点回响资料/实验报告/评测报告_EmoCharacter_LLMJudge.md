## 2. LLM-Judge 对照表（30 条样本，样本_60条_优化.json，配对总数 60/配置，种子 42）

协议：AI 回复 vs 真人回复配对盲评（AB 正反各一次）+ 1-5 分评分。

| 配置 | win_rate | average_rating | AI评分均值 | 相对纯裸提升 |
|---|---|---|---|---|
| 裸（纯净） | 0.2667 | 0.6933 | 3.47 | —（基准） |
| **P4 锚点（单模式纯净）** | 0.3000 | 0.6733 | 3.37 | **+12.49%** |
| 裸 + P3 人设（参照） | 0.3833 | 0.6667 | 3.33 | +43.72% |
| **P4 锚点 + 人设** | **0.4167** | 0.6667 | 3.33 | **+56.25%** |
| P4 锚点 + 自选N=3（纯） | 0.2167 | 0.6667 | 3.33 | -18.74% |

判定标准：单模式 win_rate 相对裸提升 ≥ +25%（裸 0.2667 → 目标 ≥ 0.3334）。

- **P4 单模式（纯净）：✗ 未达成**（0.30，+12.49%）
- **P4 + 人设：✓ 达成**（0.4167 ≥ 0.3334，+56.25%）
- **P4 + 自选N=3：✗ 负向**（0.2167，-18.74%；人味评分启发式选中了更长更书面的候选，弃用）

**归因**：人设系统提示本身把裸从 0.2667 提到 0.3833（+43.72%），是主增益来源；在同一人设提示下，锚点仍比裸高 0.0334（+8.71% 相对裸+人设），说明锚点通道在风格对齐后有正向边际增益（情感方向更贴合用户文本）。

## 3. 判定结论

| 基准 | 标准 | 结果 | 达成 |
|---|---|---|---|
| EmoCharacter | 一致性识别率 ≥ 裸×1.16（+16%） | 0.90 → 0.70（-22.2%） | ✗ 未达成 |
| EmoCharacter（SubTask 6b 备选口径） | 识别率 ≥ 裸基线(0.90) 且 相对上轮 P4(0.70) 显著回升（≥0.80），fidelity ≥ 裸-5% | 裸 0.90 → 角色感知锚点 0.70（未回升；匹配 0.8075 ≥ 0.7885 ✓） | ✗ 未达成 |
| LLM-Judge（P4 单模式纯净） | win_rate ≥ 裸×1.25（+25%） | 0.2667 → 0.30（+12.49%） | ✗ 未达成 |
| LLM-Judge（P4+人设，按序变体 a） | 同上 | 0.2667 → 0.4167（+56.25%） | ✓ 达成 |

- **达成配置**：P4 锚点解码器 + P3 人设系统提示（β=0.8, 稀疏阈值=0.0, T_anchor=0.3, K=6）。
- **EmoCharacter 判定口径说明**：裸一致性识别率 0.90 为本轮复核的事实基线（裸生成确定性可复现），
  原标准「≥ 裸×1.16」≈ 1.044 不可达 → 采用任务给出的备选口径（见 §1）。
- **未达成项说明**：角色感知锚点识别率 0.70 与上轮普通锚点持平、未显著回升（未达 ≥0.80），但① 毒舌但心软的损友
  识别 ✗→✓（裸与普通锚点均 ✗）；② 真实一致性 0.915→0.960 回升；③ 匹配 fidelity 0.8075 ≥ 裸-5%，无显著退化；
  ④ 中性下限持平，无角色情感污染。卡点收敛为 **1.5B 模型第 3/4 轮固有开头模板**（"嗯？谢谢？/太好了！"，
  裸同样存在）与打乱集雷同，非角色感知通道本身所致。
- **遗留**：后续可尝试 ①更强角色化（扩大锚点维度至 K>6 或角色专属锚点词集）；②用更强基座模型（裸模板来自
  1.5B 理解力上限）；③识别协议层面将二选一打乱集改为跨模式混合（当前打乱集取自同模式回复，模板化会被放大）。

## 5. 工程卡点与处置（记录）

1. **同进程 1.5B 生成 + 7B 裁判原生崩溃（0xC0000005）**：P3 报告指出的 torch_cpu.dll commit 内存崩溃。处置：按任务要求"生成与裁判分离进程"，评测脚本两阶段化（`--只生成` / `--只裁判` + 缓存），裁判阶段每模式独立进程运行。
2. **7B 裁判整分片装载触发"页面文件太小（OSError 1455）"**：系统 commit 紧张（另一用户进程 RVC infer-web 常驻约 7.9GB）。处置：裁判分片由"整分片装载"改为"逐张量装载"（峰值由 ~9.6GB 降至单张量 ~0.5GB），加载实测通过（可用页文件最低仍余 ~7.3GB）。
3. **脚本 `--只生成` 曾覆盖结果 JSON**：已修复（`--只生成` 只写生成缓存，不写结果文件）。
4. **SubTask 6b·`--模式 全部` 主进程 + 裁判子进程并存触发 1455**（生成阶段主进程内存未随模型 del 释放，与子进程 7B 加载叠加超 commit 限制）。处置：全程改为两阶段分步执行（`--只生成` → 每模式独立 `--只裁判`，等前一个进程退出再起下一个）。
5. **SubTask 6b·cnsenti 词库未收录"累/没用"等口语词**（实测 "累"∉Negs），用户情感测量全零 → 用户部分退化为默认温柔、跨角色雷同。处置：`目标决策器` 内置 `_简易补测()`（简易词表子串匹配）+ 扩充 `简易负面词`（没用/做不好/撑不下去 等），实测第 2/3 轮难过、第 4 轮开心方向均生效。
6. **SubTask 6b·角色感知迭代（识别率路径）**：
   - **v1** 角色感知融合（0.7·角色 + 0.3·用户）+ 原句子停止（最短12字/最长2句）→ 识别率 **0.60**（回复被截成"嗯？谢谢？/太好了！"整句）；
   - **v2** + 延长句子停止（20字/3句）→ 开头模板仍占主导（7/10 角色第 3 轮"嗯？谢谢？"开头，与裸对照确认是 1.5B 模型固有模板，非锚点引入）；
   - **v3** 去掉句子停止（与裸同长）+ 角色扰动 0.06 → **0.70**（毒舌 ✗→✓ 修复）；
   - **v4** 扰动 0.06→0.10 → 0.70（结果不变）；**v5** + max_new_tokens 64→96 → 0.70（结果不变）。
   - 结论：0.70 为当前方案稳定水平；剩余失败（同桌/竹马/脱口秀）源于 1.5B 模型第 3/4 轮固有模板与打乱集雷同。
